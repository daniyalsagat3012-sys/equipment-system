# Спецификация проекта Equipment System

## 1. Основные разделы системы

Система состоит из четырёх разделов:

1. Оборудование (Equipment).
2. Заявки (Requests).
3. Пользователи (Users).
4. Отчёты (Reports).

## 2. Функции разделов

### 2.1. Оборудование
1. Добавление оборудования.
2. Редактирование информации.
3. Удаление оборудования.
4. Поиск по названию и инвентарному номеру.
5. Просмотр технического состояния.

### 2.2. Заявки
1. Создание заявки на ремонт.
2. Просмотр заявок.
3. Изменение статуса заявки.
4. Назначение исполнителя.
5. Закрытие выполненной заявки.

### 2.3. Пользователи
1. Добавление пользователей.
2. Вход по логину и паролю.
3. Редактирование данных.
4. Назначение ролей.
5. Удаление пользователей.

### 2.4. Отчёты
1. Формирование списка оборудования.
2. Подсчёт общего количества оборудования.
3. Отчёт о неисправном оборудовании.
4. Подсчёт выполненных заявок.
5. Скачивание отчётов.

## 3. Описание данных

### Equipment
- id — число, уникальный номер.
- name — текст, название оборудования (2–100 символов).
- inventory_number — текст, уникальный номер (до 30 символов).
- price — число, стоимость оборудования.
- location — текст, местоположение (2–100 символов).
- status — текст, техническое состояние.

### Requests
- id — число, номер заявки.
- equipment_id — число, номер оборудования.
- description — текст, описание проблемы (10–500 символов).
- date — дата создания.
- status — текст, статус заявки.
- user_id — число, автор заявки.

### Users
- id — число, уникальный номер.
- name — текст, имя пользователя.
- login — текст, логин.
- password — текст, хеш пароля.
- role — текст, роль пользователя.

### Reports
- id — число, номер отчёта.
- title — текст, название отчёта.
- created_at — дата и время создания.
- user_id — число, автор отчёта.
- report_type — текст, тип отчёта.

## 4. Sequence Diagram

Процесс создания заявки:

1. Пользователь входит в систему.
2. Выбирает оборудование.
3. Нажимает кнопку «Создать заявку».
4. Вводит описание неисправности.
5. Система проверяет введённые данные.
6. Сервер отправляет данные в базу.
7. База данных сохраняет заявку.
8. Система показывает сообщение об успешном создании.

## 5. Проверка функций

### Оборудование
1. Дано: пользователь вошёл в систему. Когда: он добавляет оборудование. Тогда: запись появляется в списке.
2. Дано: оборудование существует. Когда: пользователь изменяет данные. Тогда: изменения сохраняются.
3. Дано: оборудование существует. Когда: администратор подтверждает удаление. Тогда: запись удаляется.
4. Дано: оборудование зарегистрировано. Когда: пользователь вводит инвентарный номер. Тогда: система находит оборудование.
5. Дано: информация сохранена. Когда: пользователь открывает карточку. Тогда: отображается техническое состояние.

### Заявки
6. Дано: пользователь выбрал оборудование. Когда: отправляет описание проблемы. Тогда: заявка создаётся.
7. Дано: заявка создана. Когда: пользователь открывает список. Тогда: отображается заявка.
8. Дано: заявка имеет статус «Новая». Когда: администратор меняет статус. Тогда: новый статус сохраняется.
9. Дано: заявка создана. Когда: администратор назначает исполнителя. Тогда: исполнитель отображается в заявке.
10. Дано: ремонт выполнен. Когда: исполнитель закрывает заявку. Тогда: статус становится «Завершена».

### Пользователи
11. Дано: администратор авторизован. Когда: добавляет нового пользователя. Тогда: пользователь появляется в системе.
12. Дано: пользователь зарегистрирован. Когда: вводит правильный логин и пароль. Тогда: система открывает доступ.
13. Дано: пользователь существует. Когда: администратор меняет его данные. Тогда: данные обновляются.
14. Дано: пользователь зарегистрирован. Когда: администратор назначает роль. Тогда: роль сохраняется.
15. Дано: пользователь существует. Когда: администратор подтверждает удаление. Тогда: доступ пользователя прекращается.

### Отчёты
16. Дано: оборудование зарегистрировано. Когда: пользователь запрашивает список. Тогда: система показывает оборудование.
17. Дано: есть записи об оборудовании. Когда: пользователь открывает статистику. Тогда: показывается общее количество.
18. Дано: есть заявки на ремонт. Когда: пользователь формирует отчёт. Тогда: отображается список ремонтируемого оборудования.
19. Дано: есть завершённые заявки. Когда: пользователь открывает статистику. Тогда: отображается их количество.
20. Дано: отчёт сформирован. Когда: пользователь нажимает «Скачать». Тогда: файл загружается.

## 6. Ограничения системы

1. Поддерживаемые браузеры: Google Chrome и Microsoft Edge.
2. Поддерживаемые системы: Windows 10 и Windows 11.
3. Максимальное количество записей об оборудовании: 10 000.
4. Количество пользователей: не менее 100.
5. Одновременная работа: не менее 20 пользователей.
6. Описание заявки: от 10 до 500 символов.
7. Инвентарный номер должен быть уникальным.
8. Для входа необходимы логин и пароль.
9. Административные функции доступны только администратору.
10. Основные страницы должны открываться не более чем за 2 секунды.

## 7. Замечания партнёра

После проверки проекта одногруппником необходимо записать минимум пять реальных замечаний и исправить спецификацию.

Примеры возможных замечаний:
1. Добавить проверку уникальности инвентарного номера.
2. Уточнить статусы заявок.
3. Указать ограничения длины описания.
4. Разделить права администратора и сотрудника.
5. Установить максимальное количество записей.
